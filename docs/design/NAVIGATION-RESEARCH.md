# Navigation research — how CLIs and agents "open the exact surface"

Research for the `summer open` / `summer_open` workstream (Phase 1 of three). Written 2026-09-03 from primary sources (official docs, GitHub source) fetched that day; anything not verified is marked. The design that follows from this is `NAVIGATION-DESIGN.md`; the build lands as `tool/open`, `reference/product-map`, `skill/navigate-summer`.

The question (Mathias, verbatim intent): *"What makes the Cloudflare and AWS CLIs so sexy? They have documentation of how their website works, so an agent can click around and find anything you need directly in the UI. You want to change billing — boom, it opens billing. You want to check stuff — boom, it opens it on the website AND in the native app. I want that exposed in Summer's CLI and MCP, as part of the skills."*

## 0. Verdict in five lines

1. **Nobody ships "one command, intent name, web AND native".** Products pick one: intent-named web tables (Firebase, Stripe, `gh browse`), intent-named native schemes (Steam, Things, Raycast, Roblox Studio), or URL-shaped web↔desktop mirroring (Linear, Notion, Figma, Slack). Engine MCPs open scenes and know nothing of the web; SaaS MCPs know the API and never open a UI.
2. **"The agent clicks around the website" is a misunderstanding of Cloudflare and AWS.** Both give agents *deep links + docs-as-data + API via MCP*. Cloudflare's hosted browser MCP is fetch/screenshot only; real clicking is a self-deployed Playwright MCP aimed at *other* sites. Computer-use costs ~1–2k tokens per screenshot and several round trips per click; every vendor's own guidance is "give agents a direct tool instead".
3. **What actually makes agents good at AWS is regularity generated from a machine-readable model** (one grammar, uniform help, `--output json`, `--query`, skeletons, read/write tagging), not console links — AWS console deep links are undocumented and reverse-engineered. Cloudflare's one navigation gem is the `dash.cloudflare.com/?to=/:account/:zone/...` placeholder convention, resolved *after* login.
4. **The best "intent → exact panel" artifacts are native-platform standards**: Windows `ms-settings:` (~200 documented URIs), Android App Actions `shortcuts.xml` (intent + typed params + URL template), Siri App Shortcuts (developer-authored phrases). On the web the closest is Firebase's `LINKS[]` table and Stripe's `stripe open --list`. `llms.txt` alone does not get fetched (97% of files see zero requests); discovery is *pushed* via installed skills/CLI, which is exactly Summer's distribution model.
5. **For the editor, the token-authenticated local HTTP API is the right primitive** and the engine already has the navigation ops (`OpenScene`, `SelectNode`, `OpenResource`, `FocusDock`, `RevealInFileSystem`). A `summer://` scheme is a v2 launcher-when-closed item that must forward to the same API (the VS Code pattern) — Godot has no single-instance forwarding, so a naive scheme spawns a second editor.

Recurring patterns: (1) intent shortcuts in a flat table (Stripe, Firebase, Doppler) vs path mirrors (gh) — tables are listable, mirrors serve one resource type; (2) placeholder substitution, never URL builders (Stripe `%s`→`/test`, Firebase `/project/${id}${path}`); (3) context from a link file, never prompted twice (`.vercel/project.json`, `.neon`, `.firebaserc`, git remotes); (4) print-only is inconsistent — `gh -n`, `railway --print`, `heroku --show-url`; Firebase/Netlify/pscale log the URL before opening; Stripe/Vercel/Fly have nothing; (5) `--web` as a flag on `view/show` composes with id resolution already present; (6) missing arg → interactive picker (Firebase) or table dump (Stripe `--list`); (7) everyone shells to `open`/`xdg-open`/`rundll32`, only gh honors `BROWSER`, Stripe enforces HTTPS + host allowlist; (8) llms.txt/`.md`/MCP/skills are near-universal but **none exposes the open-target table to agents in machine-readable form**.

**Verdict.** The sexy part is a flat, self-listing intent table with one or two substitution slots, context read from a link file, and a print-only escape hatch. Firebase's `LINKS[]` is the best design (colon-namespaced sub-intents, computed targets like `functions:log`, always logs the URL); Stripe's `--list` is the best discoverability. Nobody accepts a resource id even when it is the obvious ask, and Cloudflare, Supabase, Render, Turso and Expo have no dashboard opener at all in 2026 — the bar is low.

## 2. AWS

**CLI regularity is rendered from models.** `aws <service> <operation>` is generated from botocore's per-service JSON (`service-2.json`, paginators, waiters, endpoint rules, examples — https://docs.aws.amazon.com/botocore/latest/reference/loaders.html); `aws configure add-model` proves it (drop a model file in `~/.aws/models` and the commands appear — https://docs.aws.amazon.com/cli/latest/reference/configure/add-model.html); the Smithy models for every service are published at https://github.com/aws/api-models-aws, which explicitly suggests using them to implement MCP servers. Uniform escape hatches: `aws <svc> <op> help` (six fixed sections), `--generate-cli-skeleton input|yaml-input|output` + `--cli-input-json`, `--query` (JMESPath), `--output json|yaml|text|table|off`, `--cli-auto-prompt` full/partial (https://docs.aws.amazon.com/cli/latest/userguide/cli-usage-parameters-prompting.html). Read/write classification of every operation is machine-readable (Service Authorization Reference) — Kiro's `use_aws` tool (`autoAllowReadonly`) and the API MCP server (`READ_OPERATIONS_ONLY`) build their safety gates on it.

**Console deep links: predictable in practice, undocumented as a scheme.** AWS publishes per-service console *home* URLs in every guide, not a deep-link grammar; the `#/…` fragment routing is reverse-engineered — best catalog https://github.com/link2aws/link2aws.github.io (ARN → URL, ~110 services). Undocumented universal router `console.aws.amazon.com/go/view?arn=<arn>` / `/go/list?resourceType=…` (https://wut.dev/blog/2025/06/21/hidden-aws-console-go-urls.html). Officially documented: IAM Identity Center shortcut links `https://<sub>.awsapps.com/start/#/console?account_id=…&role_name=…&destination=<url-encoded console URL>` (https://docs.aws.amazon.com/singlesignon/latest/userguide/createshortcutlink.html) and federation sign-in with `Destination=`. Multi-session console changes hostnames to `<account>-<rand>.<region>.console.aws.amazon.com` — classic hosts are not guaranteed stable (https://docs.aws.amazon.com/awsconsolehelpdocs/latest/gsg/multisession.html). Examples: S3 `https://s3.console.aws.amazon.com/s3/buckets/<bucket>`; Lambda `https://<r>.console.aws.amazon.com/lambda/home?region=<r>#/functions/<name>`; CloudWatch `…/cloudwatch/home?region=<r>#logsV2:log-groups/log-group/<name>`; EC2 `…/ec2/home?region=<r>#InstanceDetails:instanceId=<id>`; IAM `console.aws.amazon.com/iam/home?#/roles/<name>`; Billing `console.aws.amazon.com/billing/home#/bills`. Console-to-Code turns a human click trail into CLI/CDK (https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/console-to-code.html).

**Amazon Q Developer CLI is now Kiro CLI** (2025-11-17): `kiro-cli chat`, `kiro-cli translate`, agents as JSON in `~/.kiro/agents` (tools/allowedTools/mcpServers/hooks/permissions), built-in `use_aws` tool (https://kiro.dev/docs/upgrade-guides/migrating-from-q/, https://kiro.dev/docs/reference/built-in-tools/).

**MCP.** Managed AWS MCP Server GA 2026-05-06 at `https://aws-mcp.<region>.api.aws/mcp` — `call_aws`, `search_documentation`, `read_documentation`, `retrieve_skill`, `run_script`, read-only mode, IAM condition keys (https://aws.amazon.com/blogs/aws/the-aws-mcp-server-is-now-generally-available/). AWS Knowledge MCP `https://knowledge-mcp.global.api.aws`, no auth (https://github.com/awslabs/mcp/tree/main/src/aws-knowledge-mcp-server). Local `aws-api-mcp-server`: `call_aws` parses the command with the CLI's own parser, `suggest_aws_commands`, `READ_OPERATIONS_ONLY`, `REQUIRE_MUTATION_CONSENT` via elicitation (https://github.com/awslabs/mcp/tree/main/src/aws-api-mcp-server). AWS Documentation MCP: `read_documentation`, `search_documentation`, `recommend`.

**Docs-as-data.** `https://docs.aws.amazon.com/llms.txt` exists (index of ~200 per-guide files; `.md` per page serves real markdown, e.g. https://docs.aws.amazon.com/lambda/latest/dg/welcome.md). Fern's Agent Score grades it D/68 — root file 288k chars, no content negotiation (https://buildwithfern.com/agent-score/company/docs-aws-amazon-com).

**Verdict (ranked contributors).** (e) training-data volume is the base and not replicable; (a) CLI regularity generated from a model is the biggest *structural* factor; (b) MCP servers are mostly the same model re-exposed plus docs search and consent gates; (d) docs-as-data is real but uneven; (c) console deep links are the **weakest** — undocumented, reverse-engineered, hostnames unstable; only Identity Center shortcuts and `/go/view?arn=` are dependable. Transferable to Summer: (a) fully — one operation model, read/write tagging, `--print`/JSON; (d) cheaply — llms.txt plus `.md` per page; (c) cheaply and *better* than AWS by publishing a stable, documented "open this id" router.

## 3. Cloudflare

**Real vs misunderstanding.** Cloudflare ships three layers for agents, none of which clicks its own dashboard: (1) **deep links** — `https://dash.cloudflare.com/?to=/:account/:zone/...`, a placeholder convention used 1,340 times across 848 docs pages via the `DashButton` component (https://developers.cloudflare.com/style-guide/components/dash-button/); the dashboard resolves `:account`/`:zone` *after* login; no page formally documents the grammar (community "Magic Linker" adds `:worker`, `:pages-project` — https://github.com/mackenly/cloudflare-magic-linker); (2) **docs for agents** — `llms.txt`, `llms-full.txt` (>10 MB), per-product `/<product>/llms.txt`, `/index.md` suffix on any page, `Accept: text/markdown`, unauthenticated Docs MCP `https://docs.mcp.cloudflare.com/mcp` (`search_cloudflare_documentation`) (https://developers.cloudflare.com/docs-for-agents/); (3) **API via OAuth remote MCP servers** — `https://mcp.cloudflare.com/mcp` (Code Mode `docs`/`search`/`execute` over 2,500+ endpoints) plus ~16 product servers (bindings, builds, observability, containers, browser, logs, ai-gateway, autorag, auditlogs, dns-analytics, dex, casb, radar, graphql, blog) (https://github.com/cloudflare/mcp-server-cloudflare; https://developers.cloudflare.com/agents/model-context-protocol/cloudflare/servers-for-cloudflare/).

**Where clicking is real.** Browser Run (renamed from Browser Rendering 2026-04-15) is a *product for building agents that browse other sites*: self-deployed `@cloudflare/playwright-mcp` (`browser_click`, `browser_type`, `browser_navigate`, … — https://github.com/cloudflare/playwright-mcp) or CDP at `wss://api.cloudflare.com/client/v4/accounts/<id>/browser-rendering/devtools/browser` for chrome-devtools-mcp (https://developers.cloudflare.com/browser-run/cdp/mcp-clients/). The *hosted* `browser.mcp.cloudflare.com` has only `get_url_html_content`, `get_url_markdown`, `get_url_screenshot`, `get_url_pdf`, `scrape_url_elements`, crawl — no click/type. WebMCP lets sites expose typed tools so agents call functions instead of clicking (https://developers.cloudflare.com/browser-run/features/webmcp/). Nothing targets dash.cloudflare.com.

**CLIs.** `wrangler` has no `open`/dashboard command (only `login` and `docs` open a browser — https://developers.cloudflare.com/workers/wrangler/commands/general/); context = `wrangler.jsonc` + `CLOUDFLARE_ACCOUNT_ID` + `wrangler auth` profiles. A unified `cf` CLI **is real** (Technical Preview, "Building a CLI for all of Cloudflare", 2026-04-13: `npx cf`, `--json`, explicitly agent-oriented, `cf context set account-id`, `cf agent-context`, `cf schema` — https://blog.cloudflare.com/cf-cli-local-explorer/) and also has no open/dashboard command. `flarectl` is legacy.

Deep-link rows verified in docs: account home `/?to=/:account/home`; Workers & Pages `/?to=/:account/workers-and-pages`; R2 `/?to=/:account/r2/overview`; zone DNS `/?to=/:account/:zone/dns/records`; billing `/?to=/:account/billing`; support `/?to=/:account/support`; API tokens `https://dash.cloudflare.com/profile/api-tokens`.

**Verdict.** "Clicks around the website" is a misunderstanding: Cloudflare's design direction (Code Mode MCP, `cf agent-context`, WebMCP) is explicitly *give agents structured tools instead of making them click*. The one thing worth stealing for navigation is the `?to=/:account/...` idea — a URL that is valid before you know the ids, resolved at the destination after login. The Agents SDK (`npm i agents`, Durable Objects) is for building agents, not for navigating Cloudflare.

Registration: macOS `Info.plist` `CFBundleURLTypes` + `application(_:open:)` (Apple: validate every component, restrict what the scheme can do — https://developer.apple.com/documentation/xcode/defining-a-custom-url-scheme-for-your-app); Windows `HKCR\<scheme>` `URL Protocol` + `shell\open\command "%1"` (Microsoft: "assume any parameters on the command line could come from malicious parties" — https://learn.microsoft.com/en-us/previous-versions/windows/internet-explorer/ie-developer/platform-apis/aa767914(v=vs.85)); Linux `.desktop` `MimeType=x-scheme-handler/<scheme>` + `update-desktop-database` (Obsidian ships none). Godot's `OS.shell_open(uri)` hands any string to the OS.

Godot `EditorInterface` (4.5 — https://docs.godotengine.org/en/stable/classes/class_editorinterface.html): `open_scene_from_path`, `edit_node`, `edit_resource`, `inspect_object`, `select_file` (FileSystemDock), `edit_script(script, line, col, grab_focus)`, `set_main_screen_editor("2D"|"3D"|"Script"|"Game"|"AssetLib")`, `popup_quick_open`, `popup_node_selector`, `play_main_scene`/`stop_playing_scene`, `get_command_palette()`. There is **no** `open_project_settings` on `EditorInterface`; the internal path is `EditorNode::get_project_settings()` → `ProjectSettingsEditor`. `EditorNode::open_request` / `select_editor_by_name` do not exist in 4.5 or master.

Other mechanisms: token-authed local HTTP is the mature pattern (Obsidian Local REST API `127.0.0.1:27124`, Bearer, `POST /open/{path}`, `POST /commands/{id}` — https://github.com/coddingtonbear/obsidian-local-rest-api; Figma desktop MCP `127.0.0.1:3845/mcp`; CoplayDev unity-mcp `localhost:8080`); *un*authenticated sockets are the anti-pattern (blender-mcp raw TCP 9876; Chrome now refuses `--remote-debugging-port` on the default profile); `osascript`/JXA and the Accessibility API are what computer-use falls back to.

**Verdict for Summer.** The editor already has the strong primitive: a per-instance, token-authenticated local HTTP API with an instance registry in `~/.summer/instances/*.json`. Execute navigation *only* through it. A `summer://` scheme buys exactly one thing the API cannot — launching the app when it is closed, and clickable links from web/chat — and costs a web-triggerable entry point plus Windows/Linux registration; Godot has no single-instance forwarding, so a naive scheme opens a second editor on the same project. If built (v2), do what VS Code does: the binary's argv handler looks up the running instance, POSTs the navigation to it and exits, else launches with the target queued; whitelisted verbs, `res://` paths only, never config or code (CursorJack). A `summer open …` CLI means terminal agents never need the scheme.

## 5. Agent-navigable product docs

`llms.txt` (https://llmstxt.org/): H1 (only required element), blockquote, H2 sections of `[name](url): notes`, an `Optional` section; `llms-full.txt` inlines everything. **No intent vocabulary, no parameters, no context requirements** — a curated sitemap, not a map of actions. Fetched examples: Cloudflare (two-level index), Stripe (`docs.stripe.com/llms.txt` opens with *instructions to the agent* — "run `stripe docs`", "never hardcode an old version"), Anthropic (`platform.claude.com/docs/llms.txt`, a `<budget:token_budget>200000</budget:token_budget>` tag, ~1,200 `.md` links), Vercel (`vercel.com/llms.txt`, a <2 KB hub → `sitemap.md`, `llms-full.txt`, `graph.json`, `taxonomy.json`), Expo (a "common misconceptions" section correcting model priors). Adoption: 36,120 files in May 2026 from 4,088 in June 2025, still ~1% of sites (https://originality.ai/blog/llms-txt-tracking-study). Consumption: Ahrefs, 137k domains — **97% of published llms.txt files received zero requests**; of requests, SEO tools 21.7%, GPTBot 4.51%, ClaudeBot 0.80% (https://ahrefs.com/blog/llmstxt-study/); Google's Mueller: "no AI system currently uses llms.txt" (https://www.searchenginejournal.com/google-says-llms-txt-comparable-to-keywords-meta-tag/544804/).

Docs MCP servers are all *search → fetch page (→ code sample)*; none exposes intent → URL/panel: Cloudflare Docs; Stripe `mcp.stripe.com` (`search_stripe_documentation`, `stripe_implementation_planner` routes to *products* — the closest to intent routing; https://docs.stripe.com/mcp.md); Vercel `mcp.vercel.com` (`search_vercel_documentation(topic, tokens)` — https://vercel.com/docs/agent-resources/vercel-mcp/tools); Supabase `search_docs`; Microsoft Learn `learn.microsoft.com/api/mcp`; Context7; Mintlify auto-serves `/mcp`, `/llms.txt`, `.md` per page and a `Link: </.well-known/mcp/server-card.json>; rel="mcp-server-card"` header (https://www.mintlify.com/docs/ai/model-context-protocol).

Ranked "intent → exact panel" today: 1 Windows `ms-settings:` (exhaustive, parameterized), 2 Android `shortcuts.xml` (intents + typed params + inventories), 3 Siri App Shortcuts (best phrase model), 4 Web App Manifest `shortcuts`, 5 Stripe `open`, 6 Cloudflare `?to=`, 7 Firebase `open`, 8 macOS.

What actually helps agents (published evidence): markdown beats HTML — Vercel 500 KB HTML → 3 KB markdown (https://vercel.com/blog/making-agent-friendly-pages-with-content-negotiation), Cloudflare optimized docs 31% fewer tokens and correct answers 66% faster (https://blog.cloudflare.com/agent-readiness/); `Accept: text/markdown` negotiation is sent by Claude Code, Cursor and OpenCode but not Codex, Gemini CLI, Copilot or Windsurf (Checkly, Feb 2026), so explicit `.md` URLs remain the durable fallback (Cloudflare `/index.md`, Vercel `.md` + `<link rel="alternate" type="text/markdown">` — https://vercel.com/docs/agent-resources/markdown-access). Discovery is *pushed*: Stripe `stripe agent setup` + `/.well-known/skills/index.json`, Vercel `npx plugins add vercel/vercel-plugin`, Cloudflare's Skills repo, Mintlify's server-card header.

**Verdict.** No product ships the artifact Summer wants — phrase → URL or editor op, with required context — so compose it: Siri's developer-authored phrase list and Android's URL template with typed, required, enumerable parameters as the schema; Cloudflare's placeholders resolved at the destination (for Summer, `?next=` through login); Stripe's self-listing and Windows' exhaustive first-party table as publishing discipline; the Web App Manifest's per-entry `description` as the one line an agent reads to disambiguate. Serve it three ways because discovery is pushed: a library reference installed with every skill set, an MCP/CLI tool that resolves a phrase to `{url | op, missing_context[]}`, and a machine-readable catalog on summerengine.com linked from llms.txt.

## 7. What Summer already has (verified in the repos, 2026-09-03)

- **Engine ops that navigate the editor** (`modules/1summer_engine/dev/op_registry/op_registry.json`, handlers in `modules/1summer_engine/editor/ops_executor.cpp` and `ops/scene_ops.cpp`): `OpenScene {path}`; `SelectNode {nodePath, scenePath?}` (selects in the tree and shows in the inspector); `OpenResource {path}` (`.tscn`/`.scn` → scene, `.gd` → script editor without grabbing focus, import-mapped assets refused); `FocusDock {dock}` with exactly three ids — `file_system | scene_tree | inspector` (`_se_resolve_dock`); `RevealInFileSystem {path}` (focuses the FileSystem dock and navigates to the path); `EditorWindowSnapshot` (local API only); `PlayGame`/`StopGame`; `ProjectSetting {key, value}` (write — not a UI open). All reachable today via `summer_batch`; `OpenScene`, `SelectNode`, `PlayGame` have dedicated tools.
- **Not an op today** (each is one small engine change): main-screen switch (`EditorInterface::set_main_screen_editor("2D"|"3D"|"Script"|"AssetLib")`), project settings dialog (`EditorNode::get_project_settings()` popup), editor settings dialog, docks beyond the three ids (Output, Debugger, Import, Node, History, the Summer assistant dock — extend `_se_resolve_dock`), bring-window-to-front (`DisplayServer::window_move_to_foreground`), open script at a line (`edit_script(script, line, col)`).
- **Richer navigation exists only behind the in-editor chat webview bridge** (`editor/docks/chat_dock.cpp::_on_webview_message`): `editor:open {file,line,col}` (switches to the Script screen and focuses), `editor:show-viewport {editor}` (`set_main_screen_editor("2D"|"3D"|"Script"|"Game")`), `editor:show-file`, `chat:open` (`ChatDock::open_chat_path` — the exact "focus the assistant" primitive), `chat:inject-message`. None is reachable over HTTP; `RunEditorScript` spawns a separate headless child, so it cannot drive the live UI either.
- **Local API** (`modules/1summer_engine/api/tool_net_thread.cpp`): binds `127.0.0.1` only, ports 6550–6565, `Host` allowlist (421 otherwise), `Authorization: Bearer <token>` on everything except `GET /api/health` (401 otherwise), token minted per boot; endpoints `GET /api/health`, `GET /api/state/<kind>`, `POST /api/ops` (202 + `requestId`, poll `GET /api/ops/result`), `POST /api/play|stop`, `GET /api/snapshot/viewport|game`.
