# Factory Droid integration

`summer setup factory` (aliases: `droid`, `factory-droid`) writes:

- MCP config: `~/.factory/mcp.json`; Windows `%USERPROFILE%/.factory/mcp.json` (user); `.factory/mcp.json` (project).
  Shape: `mcpServers.summer-engine = { type: "stdio", command, args }`.
- Skills: `~/.agents/skills` (user) or `.agents/skills` (project) as `<skill>/SKILL.md`.
- After: Restart droid or run /mcp in the active session.

Generated by `scripts/generate-registry` from `library/**/resource.yaml`:

- `registry/generated/plugin.factory.json` -> `.factory-plugin/plugin.json`
  (metadata manifest with the full skill list at
  `./library/skills/<slug>/`; version stamped from `package.json`).

The plugin marketplace is an alternative install:

```
droid plugin marketplace add https://github.com/summerengine/summer
droid plugin install summer@summer-engine --scope user
```

A plugin install reads MCP servers from the root `.mcp.json` (generated) and
skills only from a root `skills/<name>/SKILL.md` directory. Factory has no
`skills` manifest field, so the array in `plugin.factory.json` is inert and the
plugin install exposes no skills. Use `summer setup factory` to get the skills.

Never edit the destination file by hand — edit `library/` resources or
`scripts/generate-registry/manifests.ts`, then run
`npm run generate:registry`. CI `--check` fails on any drift.
