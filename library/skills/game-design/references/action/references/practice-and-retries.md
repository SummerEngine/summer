# Practice and retries

Use these comparisons when it takes several attempts to see what the player is learning, when one move appears to replace the rest, or when the meaning of another run changes after a reward. The scenes and results are hypothetical.

## An arena tutorial never asks for the response that wins the first live round

In a game about politely dueling clockwork sprites, a tutorial dummy stands still while the player practices a pulse. The player can clear the opening rounds with that move and then stalls against a sprite that periodically sends out a wave. Holding a shield through the wave creates an opening for a pulse. The creator wants players to read the sprite's state and choose whether to commit. Making the wave weaker can let the first strategy keep winning, with little evidence that players learned to read the state.

Return to the first unassisted wave and find the earliest moment the player could anticipate it. Record when they tried to shield, whether the previous pulse had ended, whether shield was allowed, and what they did on the next opportunity. If the player never tried shielding, ask “What did you think the shield was for before that round?” If the player reached for shield after a pulse, ask “When did you last have a chance to choose between the two moves?” If one player succeeds and the next cannot, check the two starting states before attributing the difference to experience.

1. If practice omitted the incoming wave, change only the dummy's behavior for one practice round. Give it a predictable wave at the original speed with the same response window. After one successful defense, give the player a different sprite that uses the same readable rule at a different interval. Earlier voluntary shields and intentional pulses after them support keeping the live window and adding that encounter to practice.
2. If shields succeed on the known interval and fail at the new one, give the new sprite the familiar cue while preserving its new timing. If correct predictions return, tune the shared cue. If players can name the imminent wave and still fail from a state where shielding is allowed, run the same live exchange from neutral with one adjusted window. That checks execution separately from choosing the wrong move before the cue.
3. If the shield command arrives during pulse recovery, restore the lead-in to the failed attempt. Ask the player to predict whether another pulse will leave enough time to shield. Keep an earlier commitment tradeoff when players can see it and their next round shows an intentional wait. Tune the earlier tell if the commitment is irreversible before any information establishes the risk. In a deliberately predictive duel, check for a prior pattern that supports anticipation instead of requiring an immediate reaction.
4. If the known counter works consistently and feels viable to the intended players, keep both moves. If one move wins from both the wave and the opening after it at equivalent cost, vary one sprite state with the same move list. If the state still gives no reason to switch, cut the redundant version from the opening or revise its purpose before adding more moves.

If the creator also wants the sprite to appear to react, keep that as a separate trial. Compare a sprite that charges its wave after the player enters range with one that charges on a timer. Match the visible windup and shield window. Ask what the player thinks caused the wave and see whether they test moving into and out of range. Keep a passive dummy when the practice goal is to rehearse inputs at the player's own pace.

## A late failure consumes the whole retry loop

Suppose the player spends fifty seconds solving familiar movement challenges before the first chance to cross a moving bridge. They can describe the bridge's cycle after a miss and stop after two runs. The creator wants the section to feel like a single sustained ascent. Check time to reach the bridge again, changes in the attempted crossing, and the condition in which the player arrives. The repeated route can provide needed setup, test consistency under continuous pressure, or consume time before the player can try their new idea.

Compare the original route with a practice restart just before the bridge. Match the state that matters, including carried charges or momentum. Give the player the same amount of play time and record how many useful attempts they choose to take. Then return to the full route and look for the improved crossing under the original pressure. If the nearby restart produces a change in approach that survives the full ascent, offer that practice or shorten the repeated approach. If improvement disappears because players arrive with different speed or resources, keep the approach in the next trial and test its specific state. If they reach the bridge often from both checkpoints and still cannot say why they missed, tune the feedback before moving a checkpoint.

Ask “What do you want the player to get better at during the approach on the third attempt?” When they name endurance or carrying resources, measure those parts on successful and failed runs. When they name the crossing alone, cut a solved stretch if players can practice the crossing with its required setup intact. Count attempts where the player gets to try a new plan. If two equally long retries give players different chances to test what they learned, use that difference to choose where to save.

## A score threshold changes what is worth doing

In a timed lantern delivery mode, the player needs enough deliveries and a safe return before the clock expires. At eleven deliveries they keep taking risky shortcuts. After the twelfth they take the long route home and decline a rematch. Before adding a new reward, inspect changes on both sides of the threshold. Prompt once with “What did you expect to gain or lose by taking the long route?”

- Keep the safe return if the player can explain why it serves a goal they care about and can still choose a risky route while chasing a personal best.
- Tune progress feedback if players continue risking a completed goal because they cannot tell when it is secured. Test a clearer threshold indicator and observe changes in route while rules and prizes stay fixed.
- If players stop at the same station to repeat an effortless delivery, remove only the repeat reward for one comparison and keep the initial payoff. Watch whether the route diversifies and whether the core target stays attainable. Cut the repeat payout if it crowds out the travel choices that define the mode.

Give one player the delivery target and another a personal best to chase, with the same clock and routes. On a replay, let each choose a goal before departure. Compare the first shortcut chosen after the target score and ask what could make another run worthwhile. If the unlock-seeker describes a complete run and elects to stop, preserve the finish. If the record-seeker can name a faster route but lacks a way to see whether it saved time, test a split shown at the next delivery.
