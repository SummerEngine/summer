# Movement and space

Use these comparisons when the report names an uncomfortable movement, an unreadable destination, or a loss of control. The scenes and results below are hypothetical.

## A jump feels heavy in a room that should invite improvisation

The creator says their paper glider should feel nimble and the first optional route should reward changing direction in midair. A player says the jump feels “heavy” after overshooting the narrow landing twice. One successful developer replay uses a short approach and a released jump. That establishes a path through the room. The player's word could refer to time between input and motion, the animation at takeoff, the amount of available correction, or the risk of committing to a landing they can barely see.

Trace one miss through approach speed, press and release, first change to upward velocity, first pose that reads as airborne, first visible landing, first reversal input, and contact. Record starting state and camera separately. Ask only the question that changes the next test. If the complaint is about feel, ask “At what point does it start to feel heavy?” If the player reports seeing the landing late, ask “Which surface were you aiming for when you pressed jump?” If they name the right surface and expect stronger steering, ask “What did you expect the direction change to do?”

| Explanation | One comparison | Decision and evidence |
|---|---|---|
| The takeoff looks delayed. | In a flat room, disable only the ribbon that drags across the floor as the glider rises. Keep poses, velocity and input handling fixed. Ask for unprompted descriptions with each version. | Tune the visual attachment if the same motion reads as more immediate and contact timing stays unchanged. If both descriptions place the delay before upward motion, inspect the acceptance and animation timestamps. |
| The landing is revealed after correction becomes ineffective. | Show the destination earlier in one copy of the room. Hold the physics and geometry fixed. In a separate observation, let a player point out the landing just before commitment. | Keep the earlier view if correct target choices appear sooner and late reversals decrease. If players already name the target and choose a viable approach, test the correction budget separately. Check camera behavior in the copy if the screen edge also constrains travel or controls respawn. |
| The player expects a long approach to have the same reach as a short one. | On two safe ledges, let the player vary one input at a time. Compare short and long approaches with the same jump hold, then tap and hold with the same approach. Return them to an unfamiliar landing with the same clearance. | Keep the controller if they can now predict which arc clears the ledge and select it without prompting. Tune the teaching ledges if they never give a reason to use both arcs. If the right arc still fails from the advertised launch area, test the geometry before widening the jump tolerance. |
| The room makes the signature jump seem ordinary. | Put the unchanged jump next to one distinctly floatier movement in one test and a more similar movement in another. Match practice time, camera and target. Use fresh descriptions before explaining the variant. | Keep the signature jump if descriptions change with the available comparison. Tune the neighboring movement or room so players can feel the intended distinction. Reopen controller tuning if the same complaint survives both comparisons and the trace shows its physical cause. |

Use two safe glider landings to isolate the cause before building another room. Put the first ledge high and close. Put the second low and far away. With the approach fixed, compare a tap and a hold at the first ledge. With the hold fixed, compare two approach speeds at the second. Record the landing point and ask for the next prediction. If the long approach also changes when the camera reveals a ledge, repeat with the destination visible from the start before attributing the miss to momentum.

If players can complete the optional route but keep stopping between jumps, ask whether they want safe passage or a smooth run. Move the existing pickups along a single feasible arc and preserve their reward value. A rise in continuous attempts alongside the same landing accuracy supports tuning the invitation. If experienced players were deliberately stopping to take a safer route, keep that choice. Cut a pickup that repeatedly signals an impossible arc. A persistent failure after players read the right arc calls for a spacing or timing comparison.

Carry the comparison method to other movement games. A route built around deliberately discovering what lies below can preserve that discovery and give players a chance to stop or retreat before the next irreversible drop. In a precision room where success depends on adapting midair, a jump comparison that removes all directional control changes the ability under review.

## Turn a story beat into a change in movement

Choose a short story or an existing beat in the game. Plot one quality, such as rising tension, in the order the player will encounter it. On a separate line, mark how much room the character has to change course, retreat, or stop. Work out what the player can actually do at each point. An early mail glider crossing might make a shortcut visible while leaving room to turn back. A later crossing might preserve the same inputs and destination but take away space for a late turn. Put a recurring side detail, such as an unused perch, off the main path and make its later appearance recognizable.

Build both crossings with simple shapes before adding story text or atmosphere. Observe where players first commit and whether they still try to reverse. Ask afterward where they felt their options narrow and what gave them that impression. If the second route confuses players and they cannot identify the reachable exit, improve the exit cue before tightening the space. If the second crossing feels more consequential while they still understand the choice, keep the layout change. In first person, test lateral exits and the distance needed to turn or retreat. Measure freedom by the actions players can still take at each point, including how much time they have to change their minds.

## A racing corner sends players wide for three different reasons

In a hover-pod time trial, players leave the track at the first tight curve. The creator wants a player to set up a line and feel the result on exit. Review attempts at comparable entry speed and record the place the player expected to slow, where inputs begin, and how the pod responds. If they never picked a place, ask “Which feature of the curve first told you to slow?” If a player points to a viable place, ask “What did the pod do when you made the input?”

- **Tune the preview.** Mark the same curve with an earlier landmark. Keep the course, vehicle and inputs fixed. Earlier chosen slowdown points and cleaner exits support the readability explanation. If players choose the same point with and without the mark, inspect what happens from input to response.
- **Tune the response feedback.** When the intended input is registered and players cannot predict the pod's path at a given speed, compare one clearer indicator of drift. Keep vehicle behavior fixed. Better predictions with continued loss of control point to the physical response or input range. If players make cleaner exits, try a new corner with the indicator removed. Continued control supports using it as a teaching cue. Improvement only while it is shown supports keeping it as live feedback if the mode calls for that help.
- **Tune input access.** If the player can steer until pressing a second control, test a reachable binding or a steering-only practice variant with predictable speed. Start from their goal. If their aim is to finish with friends, judge independent steering through the bend and perceived participation. If their goal is time-trial line mastery through deliberate speed changes, give them a reachable way to make that choice. Cut a mandatory combined input only once the revised setup still exercises the promised decision.

For a course assembled from segments, hold the pod and entry speed fixed and save one seed with a clean exit and one with repeated overshoot. A repeatable input trace can show that a line through either curve is feasible. Ask players which visible feature they used to plan that line and whether they want to take another lap. If their preferred route is slower and they can explain why they value it, check the mode's promise before tuning the course for speed.
