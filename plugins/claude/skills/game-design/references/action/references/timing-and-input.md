# Timing and input

Use these cases when the player knew the intended action and still missed, or when a general miss signal leaves the cause open. The scene and outcomes are hypothetical.

## A rhythm phrase introduces a new input and a faster pattern together

In a co-op rhythm game, a player keeps the beat in the first chorus. They miss three notes around the first lane change in the next chorus. The miss flash looks the same for a late tap, a wrong lane and no registered input. The creator is deciding whether to widen the timing window or revise this chart.

Use a familiar phrase as a baseline on the same device, sound output, chart speed and settings. In a repeatable section, record the target onset, registered input time on the chart's clock, expected and registered lanes, and the judge's result. Keep dropped inputs separate from time differences. Compare the sign and spread of input time minus target time across attempts, including attempts the judge rejected when you can map them to a specific note. If only a clip is available, locate the first visible cue and the miss flash. The clip may leave the timing of registration open.

| What the trace suggests | One comparison | Keep, tune or cut |
|---|---|---|
| Hits and near misses in the familiar phrase have a stable signed offset across lanes. | Repeat simple familiar notes before and after a measured offset correction on that setup. If comparing audio and visual paths, vary one path at a time. | Tune calibration if the offset shrinks on familiar and unfamiliar phrases. Preserve the window if the centered attempts behave as intended. An unchanged offset calls for checking where the chart, cue and judge get their time. |
| The first errors are wrong lanes around a newly introduced reach, and the beat stays steady nearby. | Give one group a sparse phrase with the new reach and another the same practice time on familiar inputs. Keep the tempo fixed. Give both an unfamiliar phrase that requires the change. | Add the sparse phrase if errors near the change decrease on the unfamiliar phrase. Improvement confined to the practiced phrase leaves transfer open. Similar errors everywhere move attention to cue visibility or timing. |
| The player calls the correct lane but their available control cannot produce it with the previous note still held. | Compare a reachable binding or one optional single-input part that keeps the same pulse and makes their contribution perceptible through their usual output. Follow the test from selecting the option to rejoining play. | Tune the mapping or part if the player can choose the timing, recognize their own contribution and wants to keep playing. Cut a mandatory chord from this route if it prevents the intended participation. The creator can keep an optional chart that requires greater reach for players seeking that skill. |
| Errors cluster where the chart's ornament masks the next playable cue. | In one duplicate phrase, reduce the ornament while keeping note times, lane positions and the acceptance window fixed. | Tune the display if correct lane choices appear earlier and misses drop at that ornament. If the right inputs are already arriving at the intended instants, inspect judgement and feedback before changing the chart. |

Choose the next interview question from the first unresolved result. For a signed offset, ask “What changes between the setups where the same phrase passes and fails?” If failure is confined to the new lane, ask “Which button or gesture did the player try there?” If an input is unreachable, ask “What part of the music does the player want to control?” If the setup is unclear, ask for one attempt with the device, calibration and output it used. A stable offset can also reflect the player's anticipation of a cue. Confirm the offset with the comparison before attributing it to the device.

Try two short parts for the same chorus. Keep the note times and the audible contribution fixed. In one part the player moves between lanes. In the other a single reachable control keeps the beat. If the promise is independent participation, check whether the player can join, keep time and hear what they contributed. If the promise is mastery of lane changes, test whether practice on a sparse phrase prepares players for the same reach in a new chorus.

Timing in a chart can use repeatable expected onsets. In a head-to-head action game, test when the information about the other player's move first became usable. In a shared performance with one global clock, slowing only one player's simulation may remove the common beat. A private practice variant or a reachable part keeps the question about participation testable.

## Rehearse one complete attempt with the available controls

Before finalizing a control scheme, choose one input setup the game claims to support and start at its ordinary entry point. Follow the setup through starting, entering play, recalling a task, acting on it, and recovering after a miss. Record the first required action that demands a different device, a simultaneous press, or a hold the player cannot sustain. Repeat the common interaction once or twice to expose extra cursor travel or recurring holds. A rehearsal with restricted inputs can reveal those demands. Use the affected player's own setup and account to judge effort and whether the alternative works for them.

For a glider with a task reminder shown only while a modifier is held, offer a tap to pin or dismiss the reminder on the same route. Compare whether the player can recall the next action while maintaining movement. Keep the route and response window fixed for that test. If reading requires time the encounter still consumes, try read-ahead or paused review in a separate trial, according to the mode's intended pressure. If the player reaches the task and still cannot make the maneuver, continue the input trace at that maneuver. After a miss, check whether the reminder returns in the state the player chose and whether the retry can begin from the same controls.

## A visible prompt hides the cause of a missed action

A crystal gate accepts an orb only while its ring is lit. The player presses while approaching at an angle and sees the generic “miss” flash. Record physical direction input, resolved direction, the gate's open interval, and whether the command arrived or was held while the avatar was committed to another move. If the diagonal resolves to a direction the player repeatedly rejects, test one direction rule at the same corner and leave the gate unchanged. Fewer mismatches support tuning command interpretation. Correctly resolved inputs rejected at the end of recovery support testing either a short input buffer or clearer feedback for a deliberate lockout. Track unwanted automatic actions after the buffer as well as successful attempts.

When the gate's warning is audible outside the camera view, run the same room with audio unavailable and compare a timed visual signal conveying the relevant event and location. Ask which gate is about to open before the window closes. If the cue only becomes understandable on replay, test earlier onset or a position closer to where the player is already looking. If it works, repeat with the player's regular output setup and check that two simultaneous cues remain distinguishable. A stronger cue preserves timing as the player's job while making a response possible. A long caption may work during a conversation and arrive too late during a timed exchange.

Use two approach angles to check whether the direction rule needs to be specific to the gate. A discrete target needs a predictable way to resolve a diagonal. Steering into position may require preserving both axes until the player actually commits. Record which gate the player intended to target, which one the command resolved to, and whether the selected gate was available at that instant.
