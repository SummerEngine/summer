# Economies, simulation and progression

Trace one resource, ability, or piece of information from acquisition to a use the player values. Mark when the investment first changes another decision. For repeat-run games, inspect the current run and the next run separately. A visible increase in a number can conceal a reduction in what the player actually gets to choose.

| Genre and question | Small experiment and decision |
|---|---|
| **Action RPG / loot hunt.** Does the game need another rarity tier? | At a representative drop, ask players which encounter the item would change and why. Give one current item a legible tradeoff and replay a familiar fight. If players try a different tactic, test more distinctive items. If they already understand the choice but see the same drop repeatedly, inspect distribution. |
| **Party RPG.** Do underused companions need a new ability? | Set up one encounter in which an underused companion's existing action can change the plan. Let the player preview its effect. If the companion now earns a slot, improve chances to see that use. If swapping costs more than the benefit even when understood, test the swap cost. |
| **Roguelike.** Is random variation creating a new decision? | On a few saved seeds trace the first branch where inventory, threat, or escape opportunity changes the player's plan. Hand-edit one repeated branch to expose two different costs. If decisions already vary and players can explain them, inspect repeated presentation before expanding generation. |
| **Roguelite.** Does persistent power teach the game or let players skip it? | Compare two starts of the same encounter with and without an inherited benefit. Follow both with an unfamiliar equivalent at equal power. If completion rises only when the benefit is active and players miss the learned response later, reconsider the benefit's timing. Carryover can still serve a power-fantasy promise. |
| **Survivor-like / horde survival.** Are upgrades altering how the player moves? | Run the same swarm from a saved state with two competing upgrades. Trace where players move, which targets they approach, and when they retreat. If the path is identical and only kill speed changes, test a tradeoff in reach or positioning when build expression is a goal. |
| **Survival crafting.** Is gathering creating planning or merely travel time? | Give players a first shelter deadline. For a second trial bring one routine ingredient closer while retaining the choice between a safe route and a dangerous shortcut. If preparation choices survive and the return trip shrinks, tune placement. Keep the distance if it creates the decision about when to turn back. |
| **Factory / automation.** Does the player need another machine? | Trace one batch from available inputs to a buyer or another station that can use it. If a working station has a queue of inputs and its output sells out, test a second copy. If finished goods already pile up, adding capacity there will increase stock. If players can repair the line once they see a blocked connection, improve inspection. Try a new machine type when the intended product needs a transformation the existing tools cannot perform. |
| **City builder / colony management.** Are failures too harsh or too hard to trace? | Replay the first shortage from a healthy save. Ask where the chain first failed, then reveal one existing dependency at that point. If players can now plan a different response, keep the consequence. If they understand it but every response arrives too late, test the warning or recovery window. |
| **Farming / life sim.** Does a calendar create anticipation or make self-directed players feel late? | Offer the same season with one daily chore made optional. Observe whether players choose a personal goal and can explain what they deferred. If choice expands without losing the seasonal rhythm, loosen the chore. If they feel aimless even with spare time, test how goals become visible. |
| **Creative sandbox / builder.** Is a blank start liberating or preventing a first creation? | Give new players a blank plot or an editable half-finished object with the same tools. Observe the first self-chosen edit, then offer a blank plot to both. Keep an optional starting point if it enables independent creation. Preserve immediate blank access for players who arrive with a plan. |
| **Idle / incremental.** Does checking back change a decision? | Simulate a short return and an overnight return. Ask what the player can now choose, then remove one collection tap on paper. If the same meaningful purchase remains and players welcome the shorter return, cut the tap. Preserve it if that moment of collection is itself valued. |
| **Extraction.** Would more loot make the decision to stay interesting? | At a known exit, record what the player thinks they are risking and what one more room could offer. Make the exit state legible while keeping rewards fixed. If players begin leaving at different times for reasons they can name, improve information. If everyone always stays even with full information, inspect the risk or marginal reward. |
| **Physics construction.** Do players need new parts or a different load to support? | Give both trials the same struts, joints and anchors. Ask for a platform that holds one crate in the center, then replay with the same crate sliding from one end. If players add bracing or redistribute support in response, vary loads before adding parts. If the same structure handles both, test a load it cannot already support. |

## Test what one mode changes in the next

In a festival prototype, the player places a water stop during setup and then ushers visitors through the grounds. Tired visitors pause at the stop before they can proceed. Mark the same stop beside the gate in one plan and beside the stage in another. From the same guest queue, ask the player to predict who can reach the stage before opening and to choose who to guide first. Watch whether they adapt their route or start placing the stop differently after seeing it in use. If players understand the link and still have the same ushering plan in both versions, test one route whose timing changes with the stop. If the setup is meant to be a quiet break between crowds, ask whether players value it on those terms.
