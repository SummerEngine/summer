# Reconstruct a player decision

Choose one moment where the player does something plausible and gets an unexpected result. Start with the exact build, route, input setup and the player's experience with the mechanic. If your material is a recording, use what is visible and ask for missing context when it would change the diagnosis.

## Trace the decision from cue to result

1. Save or note the state just before commitment. Include what the camera shows, the information already encountered, available actions and what a mistake costs. Mark the last chance to redirect, cancel or ask for help.
2. If you can pause without changing the experience, ask the player what they expect to happen and what they intend to do. In a timed scene, let the attempt finish and use an immediate replay or still frame. Preserve the difference between a prediction and an explanation made after the result.
3. Record the input, target, visible response and state change. Describe any correction or retry. Write at least two explanations for where the player's plan diverged from the design.
4. Change the earliest plausible cause for one version. Keep outcomes and options fixed for a cue test. Use fresh players for a reveal that cannot be unlearned. For repeatable tests, alternate which version comes first and note practice effects.

## Work one crossing

In an observatory, the player must cross a service floor unseen. A custodian checks the room through a moving inspection window. The player can see the light on a nearby wall but cannot see the floor from the approach. At the first crossing, ask where they expect to be visible, when they would move and which cue informed the plan.

Try a short reflection that indicates which aisle the custodian is checking. Keep the route and detection timing fixed. Then, if needed, try a separate version that displays the exact floor area. Fewer unexpected detections after the reflection support a cue change. Accurate predictions with the same failed crossings point to movement or timing. If the exact view makes an already predictable crossing dull, inspect what the remaining uncertainty contributed. In a precision challenge, giving exact information may serve the intended decisions.

## Compare other points of failure

| Observation | One comparison | What would change the next edit |
|---|---|---|
| After a camera cut, the player first moves towards the wrong target. | Use a continuous view for that action. Match enemy positions, timings and input. | Fewer wrong-direction moves support a continuity problem. Repeated errors toward the same hidden threat warrant a threat-cue check. |
| The player trusts a regional pact will survive a tariff and then calls its collapse arbitrary. | Show the existing pact consequence beside the commitment. Use the same starting state. | Better predictions show what the cue conveyed. Predicted harm followed by the same choice can be a deliberate cost. Preserve unknown rival intentions if interpreting them is the challenge. |
| Investigators reach the right answer by trying every exhibit. | Express one clue as an observable fact in the world. Keep the answer, inventory and retry rule fixed. Ask for the link before the attempt. | Reasoned first attempts support the change. Faster guesses with unchanged reasoning point to salience alone. |
| Players skip settlement work as an interruption. | Show the effect of one change to the settlement on the next expedition. Keep the benefit fixed. | Ask players to predict the effect. Deliberate actions following those predictions support the cue change. Accurate predictions with little interest point to the settlement choices or the pause in pace. |
| A chain reaction appears arbitrary even though every step obeys a rule. | Stagger the visible state changes in one replayable case. Keep resolution order and values fixed. | Ask the player to explain the sequence and predict a second case. If it takes too long to watch once understood, try a faster repeat mode. |
| A player has a specific plan for a second attempt but quits before it. | Save a checkpoint one encounter earlier. Preserve the resources, placements and decisions needed to test the plan. | A targeted adjustment supports reducing the return time. If the saved state has already made the plan impossible, put the retry before the decision that matters. |

End with the player's prediction, the decision they could actually make, the result, the suspected cause and a comparison that would change your recommendation. Keep private hypotheses about the player separate from the behaviour you can point to.
